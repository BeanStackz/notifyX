NotifyX Backend API

Offline reference for the multi-tenant notification service: organizations, projects, API keys, asynchronous notification delivery, tracking, analytics, billing, and operations.

About NotifyX

NotifyX lets users create organizations and projects, issue project-scoped API keys, and submit idempotent email notifications. Accepted notifications are stored with an outbox event and processed asynchronously through RabbitMQ and the configured provider.

This file is self-contained. Save or copy API-reference.html and open it directly in a browser; no backend, local server, Swagger installation, or network connection is required.

Authentication and responses

  • JWT: protected user and management endpoints require Authorization: Bearer <access-token>.
  • Project API key: ingestion endpoints require X-NotifyX-API-Key.
  • Public auth: register, login, and refresh do not require a JWT; logout does.
  • Provider webhooks: Brevo uses X-Brevo-Webhook-Key or a Bearer webhook secret; Razorpay uses its signature and event-ID headers.

Most successful responses use this envelope. Webhook responses are empty.

{
  "success": true,
  "message": "Request completed successfully",
  "data": {},
  "timestamp": "2026-01-01T12:00:00Z"
}

Projects

A project belongs to an organization and isolates its notifications and API keys. It has a name, a slug unique within its organization, an optional description (up to 500 characters), a lifecycle status, and creation/update timestamps. Organization owners and administrators can create, update, and archive projects; members can list and view them.

Project slugs are lowercase alphanumeric values separated by single hyphens. Archived projects cannot be updated or used as active notification destinations.

Request shapes

All request bodies are JSON. Fields not listed as required are optional unless the endpoint description says otherwise.

Authentication and profile

  • RegisterRequest: fullName, email, password.
  • LoginRequest: email, password.
  • RefreshTokenRequest: refreshToken.
  • UpdateProfileRequest: fullName.

Organization and project management

  • CreateOrganizationRequest: name, slug.
  • CreateProjectRequest / UpdateProjectRequest: name, slug, optional description.
  • CreateApiKeyRequest: name, optional expiresInDays (1–3650).

Notifications and billing

  • CreateNotificationRequest: required channel, recipient, content; optional subject, metadata, scheduledAt. Also requires the Idempotency-Key header.
  • SelectPlanRequest: planCode.
  • VerifyPaymentRequest: razorpayOrderId, razorpayPaymentId, razorpaySignature.
  • VerifySubscriptionPaymentRequest: razorpayPaymentId, razorpaySubscriptionId, razorpaySignature.

Scheduling note: scheduledAt is accepted and stored, but the current outbox publisher does not delay delivery until that time.

Authentication

POST/api/v1/auth/registerPublic

Creates a user account. Body: RegisterRequest.

POST/api/v1/auth/loginPublic

Validates credentials and returns access and refresh tokens. Body: LoginRequest.

POST/api/v1/auth/refreshPublic

Exchanges a valid refresh token for a new token pair. Body: RefreshTokenRequest.

POST/api/v1/auth/logoutJWT

Revokes the supplied refresh token for the authenticated user. Body: RefreshTokenRequest.

Profile

GET/api/v1/users/profileJWT

Returns the authenticated user's profile access information.

PUT/api/v1/users/profileJWT

Updates the authenticated user's display name. Body: UpdateProfileRequest.

Organizations

POST/api/v1/organizationsJWT

Creates an organization and adds the authenticated user as its owner. Body: CreateOrganizationRequest.

GET/api/v1/organizationsJWT

Lists organizations the authenticated user belongs to.

GET/api/v1/organizations/{organizationId}JWT

Returns one organization if the authenticated user is a member. Path parameter: organizationId (UUID).

Projects

POST/api/v1/organizations/{organizationId}/projectsJWT

Creates a project. Requires organization owner or administrator privileges. Body: CreateProjectRequest.

GET/api/v1/organizations/{organizationId}/projectsJWT

Lists projects in an organization the authenticated user belongs to.

GET/api/v1/organizations/{organizationId}/projects/{projectId}JWT

Returns a project in the specified organization. Path parameters are UUIDs.

PUT/api/v1/organizations/{organizationId}/projects/{projectId}JWT

Replaces project name, slug, and optional description. Requires organization owner or administrator privileges. Body: UpdateProjectRequest.

PATCH/api/v1/organizations/{organizationId}/projects/{projectId}/archiveJWT

Archives a project. Requires organization owner or administrator privileges. This API does not reactivate archived projects.

API keys

POST/api/v1/organizations/{organizationId}/projects/{projectId}/api-keysJWT

Creates a project API key. The secret is returned only once. Body: CreateApiKeyRequest.

GET/api/v1/organizations/{organizationId}/projects/{projectId}/api-keysJWT

Lists project API-key metadata; secret values are not returned.

DELETE/api/v1/organizations/{organizationId}/projects/{projectId}/api-keys/{apiKeyId}JWT

Revokes an API key belonging to the specified project. Path parameters are UUIDs.

Notification ingestion

GET/api/v1/ingest/whoamiAPI key

Returns the project identity associated with the supplied X-NotifyX-API-Key.

POST/api/v1/ingest/notificationsAPI key

Accepts a notification for asynchronous delivery and returns 202 Accepted. Requires X-NotifyX-API-Key and Idempotency-Key headers. Body: CreateNotificationRequest. Idempotency is scoped to the project.

Delivery tracking

GET/api/v1/projects/{projectId}/notificationsJWT

Lists notification history for a project accessible to the authenticated user.

GET/api/v1/projects/{projectId}/notifications/{notificationId}JWT

Returns notification state, provider delivery attempts, and lifecycle events. Path parameters are UUIDs.

POST/api/v1/projects/{projectId}/notifications/{notificationId}/retryJWT

Queues another delivery attempt for the notification. Path parameters are UUIDs.

Provider webhooks

POST/api/v1/webhooks/brevoWebhook

Processes a raw Brevo delivery event. Authenticate with X-Brevo-Webhook-Key or Authorization: Bearer <webhook-secret>. Returns an empty response.

POST/api/v1/webhooks/razorpayWebhook

Processes a raw Razorpay event after signature verification. Requires X-Razorpay-Signature and x-razorpay-event-id. Returns an empty response.

Analytics and operations

GET/api/v1/organizations/{organizationId}/analyticsJWT

Returns notification counts by status/channel, daily totals, and delivery rate. Optional query parameter days accepts 7 or 30; defaults to 30.

GET/api/v1/health/operationsJWT

Reports RabbitMQ and Brevo status, pending outbox backlog, and dead-letter queue count.

GET/api/v1/admin/dashboardJWT

Returns aggregate user, organization, project, and notification counts. Requires the ADMIN role.

Plans and billing

GET/api/v1/plansJWT

Lists plans with pricing, quota, rate limits, priority, and allowed channels.

POST/api/v1/organizations/{organizationId}/billing/checkoutJWT

Creates a Razorpay billing order for the selected plan. Body: SelectPlanRequest.

POST/api/v1/organizations/{organizationId}/billing/verifyJWT

Verifies payment for an organization billing order. Body: VerifyPaymentRequest.

GET/api/v1/organizations/{organizationId}/subscriptionJWT

Returns current subscription status and remaining notification quota.

POST/api/v1/organizations/{organizationId}/subscription/checkoutJWT

Starts a Razorpay subscription checkout. Body: SelectPlanRequest.

POST/api/v1/organizations/{organizationId}/subscription/{subscriptionId}/verifyJWT

Verifies checkout details; activation completes asynchronously through the provider webhook. Body: VerifySubscriptionPaymentRequest.

POST/api/v1/organizations/{organizationId}/subscription/cancelJWT

Schedules cancellation of the current organization subscription.

NotifyX API v1. This offline reference is a snapshot of the backend routes; refresh it when API routes or behavior change.

When the backend is available, the generated OpenAPI specification and interactive Swagger UI are served by the application.
